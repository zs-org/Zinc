Introduction to Fundamental Zinc

Fundamental Zinc (FZ) is the core, minimal, explicit form of the Zinc language. It is designed for systems programmers who demand total control over memory without the mental overhead of hidden allocations.

Zinc's philosophy is "Explicit is better than implicit." Every byte of heap memory is accounted for using one of five clear strategies. There is no garbage collector, no hidden control flow, and no magic.

FZ serves as the foundational layer for higher-level Zinc constructs, but it is also a powerful tool for writing clean, predictable Zig code.

Quick Start

To start with Zinc, create a file named hello.zn:

import std

pub fn main() {
    local message: []u8 = "Hello, Zinc!".dup()
    zig {
        @import("std").debug.print("{s}\n", .{message});
    }
}

Run the transpiler:

python3 fzc.py hello.zn

This generates hello.zig, which you can then compile with the standard Zig compiler.

The Basics

Zinc follows a similar syntax to Zig but introduces specific keywords for memory management. Standard Zig keywords like fn, pub, struct, if, while, etc., are passed through directly.

Stack Variables

Use const and var for standard stack-allocated variables.

const x: i32 = 10
var y: i32 = 20

Memory Strategies

Zinc provides five distinct strategies for heap and managed memory:

1. local — Function-Scoped Arena

Allocates memory in an arena that is automatically freed when the function returns. Perfect for temporary data used throughout a function.

fn foo() {
    local a: Foo = Foo()
    // 'a' is automatically freed at the end of foo()
}

2. def — Block-Scoped Heap

Safe heap allocation tied to the current block. It is automatically cleaned up (via defer) when exiting the block.

{
    def x: i32 = 42
    // 'x' is freed here
}

3. safe — Manual Checked Heap

For long-lived objects. You must explicitly call free(x). FZC will report an error if you forget to free a safe variable.

safe x: Data = loadData()
// ...
free(x)

4. fix — Fixed Buffer Allocation

Uses a fixed buffer on the stack. No heap allocation occurs. Must be used inside a fixblock.

fixblock(1024) {
    fix buffer: [100]u8 = undefined
}

5. raw — Unmanaged Heap

Direct heap allocation without automatic cleanup or leak checking. For advanced or performance-critical use cases.

Ownership & Moves

Zinc uses move semantics to manage ownership of heap-allocated data (def, safe, raw).

Move

Transfers ownership from one variable to another. The source variable becomes null.

move x -> y

Borrow

Creates a reference without taking ownership.

borrow x -> ref

Zig Integration

Zinc is designed to interoperate seamlessly with Zig.

Escape Hatch

Use zig { ... } to embed raw Zig code directly into your Zinc source.

zig {
    @import("std").debug.print("Hello from Zig!\n", .{});
}

Builtins & Keywords

Zig builtins (like @sizeOf) can be used directly. To use a Zig keyword that might conflict with Zinc or to ensure it's passed through, use the @@ prefix: @@addrspace.

Safety & Errors

FZC performs static analysis to ensure memory safety:

  • Leak Detection: Warns if a safe variable is not freed or moved.
  • Safe Runtime: free() is idempotent (safe to call multiple times) and poisons the pointer by setting it to null.
  • No Escaping: local and def variables are restricted to their respective scopes.

The Module System

Zinc modules are files ending in .zn. You can import other modules using the import keyword.

import math
import graphics as gfx

fn main() {
    const result = math.add(1, 2)
    gfx.clear()
}

FZC automatically tracks all imports and transpiles them in a single run, ensuring that your entire project is kept in sync.

Using the Compiler (FZC)

The FZC transpiler is designed to be lightweight and fast. It operates directly on the source text, performing necessary transformations to emit valid Zig code.

Command Line Usage

python3 fzc.py <entry_point.zn>

FZC will:

  1. Parse the entry file.
  2. Identify all import statements.
  3. Recurse into imported files.
  4. Apply memory strategy transformations.
  5. Emit .zig files in the same relative locations.
